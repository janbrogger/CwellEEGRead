## A. MORGOTH (bdsp-core/morgoth)

### What it is
- Name: MORGOTH = "Multi-domain Omnibus for Reading and Generalizing Over Thorough EEG Interpretation". Clinical-EEG foundation model (VQ tokenizer + 12-block transformer + task heads) giving event-level and EEG-level probabilities for: Normal/Abnormal, Slowing (none/focal/generalized), Burst suppression, Spike (yes/no), Spike localization (none/focal/generalized), IIIC (Other/Seizure/LPD/GPD/LRDA/GRDA), sleep staging 5-stage (W/N1/N2/N3/REM) and 3-stage (W/N1/N2). **[verified: README]**
- Paper: Sun C, Karakis I, Herlopian A, ... Jing J. Trained on 18,677 patients from 4 Boston hospitals (MGH, BWH, BIDMC, BCH), externally validated on 1,573 patients / 48 sites. Senior/co-authors include M. Brandon Westover and Jin Jing. **[search-snippet]**

### Input expectations **[verified: utils.py ContinuousToSnippetDataset, data_provider.py, discrete_event_level.sh]**
- Formats: `--data_format edf` or `mat` (`.pkl` for pre-processed). Raw clinical EDF is fine; preprocessing is automatic: resample to **200 Hz** (128 Hz for the SPIKES model), band-pass 0.5–70 Hz, notch 50 and 60 Hz, common-average montage (unless `--already_average_montage yes`), clip ±500 µV, per-channel scaling, windowing into **10 s snippets (1 s for SPIKES)** with a sliding step (`--prediction_slipping_step_second 1` or `--prediction_slipping_step <points>`).
- Channels: needs the **19 standard 10-20 electrodes**. Channel-name normalisation in `utils.py`: strips "EEG"/"POL" prefixes, upper-cases, removes parenthesised text and anything after "-" (so `EEG Fp1-Ref`, `FP1-AVG`, `Fp1(1)` → `FP1`). Accepted sets: `eeg_channels1 = FP1 F3 C3 P3 F7 T3 T5 O1 FZ CZ PZ FP2 F4 C4 P4 F8 T4 T6 O2` or `eeg_channels2` with modern names `T7 P7 T8 P8` instead of `T3 T5 T4 T6`. Sleep 5-stage model needs `F3 C3 O1 F4 C4 O2` (or `-M1/-M2` referenced). Missing channels → error unless `--allow_missing_channels yes` (zero-filled). If the first channel name contains `-AVG` the data is treated as already average-referenced.
- Sampling rate: taken from the EDF header; `--sampling_rate 0` means "use file value". Units are read as µV via MNE (`get_data(units='uV')`) so the EDF physical dimension must be correct (uV). `--polarity -1` inverts signal (needed for some vendors' exports, e.g. their "Sandor" EDF set).
- Duration: no hard minimum in inference, but snippets must exist (≥10 s; ≥1 s for spikes). Snippets that are flat (<2 µV, or <20 µV for spikes), saturated (>3000 µV) or constant are dropped; if none are valid the CSV is filled with zeros/"class 0". The EEG-level heads were designed around 10-minute segments; the long-EEG helper segments into 600 s EDFs for GPU memory reasons.
- Input directory: `--eval_sub_dir <dir>` is scanned recursively for `*.edf`; results are keyed by file basename.

### Running inference on a single EDF (what run.sh should do) **[verified from scripts]**
```bash
mkdir -p in && cp "$EDF" in/study.edf
# 1. event-level, one task at a time (repeat for each TASK/CKPT pair)
python finetune_classification.py --predict --abs_pos_emb --model morgoth_backbone_base \
  --task_model checkpoints/NORMAL.pth --dataset NORMAL \
  --data_format edf --sampling_rate 0 \
  --already_format_channel_order no --already_average_montage no --allow_missing_channels no \
  --max_length_hour no --leave_one_hemisphere_out no --polarity 1 \
  --eval_sub_dir in --eval_results_dir out/pred_NORMAL_1sStep \
  --prediction_slipping_step_second 1 --rewrite_results yes \
  --device cpu --distributed False        # or torchrun --nproc_per_node=1 ... without these two
# 2. EEG-level summary from the 1-s-step event CSVs
python EEG_level_head.py --mode predict --dataset NORMAL \
  --task_model checkpoints/NORMAL_EEGlevel.pth --test_csv_dir out/pred_NORMAL_1sStep --result_dir out
```
Task ↔ dataset ↔ nb_classes: NORMAL 1, BS 1, SPIKES 1, FOC_GEN_SPIKES 3, SLOWING 3, IIIC 6, MGBSLEEP3stages 3, SLEEPPSG 5. SLOWING/FOC_GEN_SPIKES/BS/sleep examples pass `--already_average_montage yes` only when input is pre-averaged MAT; for raw EDF use `no`. For >~1 h EEGs on GPU use `python segment_long_eeg.py segment --data_format edf --segment_duration 600 --eeg_dir raw --eval_sub_dir segs`, run prediction on `segs`, then `python segment_long_eeg.py combine --eval_results_dir ... --combined_results_dir ...` (README warns naive concatenation is off by the sliding-window padding).

### Output format **[verified: finetune_classification.py, EEG_level_head.py]**
- Event level: one CSV per input file, `<eval_results_dir>/<basename>.csv`, one row per sliding step. Binary tasks: single column `pred` (probability). Multi-class: columns `class_0_prob … class_{n-1}_prob` plus `pred_class` (int argmax); column order matches the README class lists (e.g. IIIC: Other/Seizure/LPD/GPD/LRDA/GRDA). SPIKES optionally also writes `<basename>_10s.csv` (`--need_spikes_10s_result yes`). `--eeg_montage single` writes per-channel columns `pred_<CH>`.
- EEG level: `<result_dir>/pred_EEG_level_<TASK>.csv` with columns `file_name, probability, pred_class_p, confidence, pred_class` (predict mode) or `file_name, probability, pred_class, true` (test mode); sleep summaries in `pred_EEG_level_SLEEP_5stage.csv` / `_3stage.csv`.
- No JSON output; a wrapper should convert these CSVs to JSON. `export_model.py` can export a task model to ONNX / TorchScript / INT8 if a lighter runtime is wanted.
- Downstream example: bdsp-core/NESI uses Morgoth on 10-min segments to produce a 591×17 feature matrix (https://github.com/bdsp-core/NESI). **[verified README]**

### C1. EEGLAB import-plugin structure **[verified: design_plugin.md from sccn/sccn.github.io, eeglab.m, plugin_install.m, neuroscanio example]**
- Discovery: at startup `eeglab.m` scans `<eeglab>/plugins/*` (and warns if `./plugins` in cwd shadows it); for each sub-folder it does `addpath(folder)`, looks for `eegplugin*.m` inside, and calls it. Files named `eegplugin_*.m` placed directly in `plugins/` also work. Folder name convention `name+version`, e.g. `cadwellio1.0.0` — `parsepluginname()` splits trailing digits/dots/underscores off the folder name to get the version (underscores → dots); if the folder name embeds the function's name (`eegplugin_<name>`) that is used as the plugin name. The version string returned by the eegplugin function is what the plugin manager compares to the server list.
- `eegplugin_<name>.m` signature: `function vers = eegplugin_<name>(fig, trystrs, catchstrs)`; must accept exactly 3 args; return `vers = '<name><version>'` e.g. `'neuroscanio1.8'`. Register menus with `uimenu` on handles found by tag: `findobj(fig,'tag','import data')` (File → Import data), `'import event'`, `'import epoch'`, `'export'`, `'tools'`, `'plot'`. Callback pattern for an importer:
  ```matlab
  cb = [ 'try, [EEG LASTCOM] = pop_cadwell;' catchstrs.new_and_hist ];
  uimenu( findobj(fig,'tag','import data'), 'Label', 'From Cadwell SQLite (.eas/.ez3) file', 'CallBack', cb, 'Separator', 'on');
  ```
  `catchstrs.new_and_hist` stores the new dataset and pushes LASTCOM into history; `store_and_hist` for in-place modifications; `trystrs.check_data / check_cont / check_epoch / check_ica / check_chanlocs / no_check` prepend dataset checks. Optional `'userdata','startup:on;study:on'` controls when the menu is enabled.
- `pop_<name>.m` conventions: `[EEG, com] = pop_cadwell(filename, 'key', val, ...)`; with no args pops a GUI (`uigetfile` + `inputgui`/`supergui`); must return `com` = the exact command string re-creating the call (e.g. `sprintf('EEG = pop_cadwell(''%s'');', fullfile)`) for history; build EEG via `EEG = eeg_emptyset; EEG.data (nbchan x pnts, single), EEG.srate, EEG.nbchan, EEG.pnts, EEG.xmin=0, EEG.chanlocs = struct('labels', names), EEG.event(i).type/.latency (samples, 1-based)/.duration, EEG.setname, EEG.comments`, then `EEG = eeg_checkset(EEG,'eventconsistency'); EEG = eeg_checkset(EEG,'makeur');` (see `pop_loadcnt.m` lines 142–232).
- Zip layout: the plugin manager downloads the zip to `plugins/tmp.zip`, creates `plugins/<name><version>/`, unzips into it, and if the zip contained a single top-level folder it moves the files up (`plugin_install.m`). So a zip whose root contains `eegplugin_cadwellio.m`, `pop_cadwell.m`, helper `.m`, `README.md`, `LICENSE` (GPL-compatible recommended; core plugins are GPL-2+) works; a single top-level folder also works. Keep the version in the folder name and in `vers` identical (eeglab issue #127 is about mismatches).

### C2. FieldTrip fileio readers **[verified: fileio_dataformat.md, dataformat_own.md, fileio.md, ft_read_header.m, ft_read_event.m, ft_filetype.m]**
- API: `hdr = ft_read_header(f)`, `dat = ft_read_data(f,'header',hdr,'begsample',b,'endsample',e,'chanindx',idx)`, `evt = ft_read_event(f,'header',hdr)`; each is a common prologue + big `switch` on the format + common epilogue. Required `hdr` fields: `Fs, nChans, nSamples (per trial), nSamplesPre (0 for continuous), nTrials (1 for continuous), label (Nx1 cell)`, optional `chantype`, `chanunit` (Nx1 cells; `ft_read_data` uses `chanunit` for unit scaling), `orig` (format-specific). Data: `Nchans x Nsamples` double (or `Nchans x Nsamples x Ntrials`). Events: struct array with `type, sample (1-based), value, offset, duration`; for pseudo-continuous block formats (EDF) add `'trial'` events per block if `nTrials>1`.
- Two integration routes:
  1. **External reader function without touching FieldTrip** (recommended for lab-specific formats): write `cadwell_sqlite.m` on the path with three call forms `hdr = cadwell_sqlite(filename)`, `dat = cadwell_sqlite(filename, hdr, begsample, endsample, chanindx)`, `evt = cadwell_sqlite(filename, hdr)`; then either pass `'headerformat','cadwell_sqlite','dataformat','cadwell_sqlite','eventformat','cadwell_sqlite'` to the ft_read_* calls / `cfg.headerformat` etc. in `ft_preprocessing`, or nothing at all if `ft_filetype` returns `'unknown'` and FieldTrip falls through. The fallback lives in each function's `otherwise` branch: `if exist(headerformat,'file'), hdr = feval(headerformat, filename); elseif fallback=='biosig' ... else ft_error('unsupported header format')`; events: `event = feval(eventformat, filename, hdr)` (calls `feval(eventformat, filename)` first if `hdr` is empty). Examples in `fileio/private/`: `biopac_acq.m`, `snirf.m`, `motion_c3d.m`, `qualisys_tsv.m`, `liberty_csv.m`, `sccn_xdf.m`.
  2. **Upstream contribution**: add a detection clause to `ft_filetype.m` (one long if/elseif ladder; order-sensitive, so use the most stringent test first: `filetype_check_extension(filename,'.eas') && filetype_check_header(filename,'SQLite format 3')` — the SQLite magic string is the first 16 bytes — then set `type='cadwell_sqlite'; manufacturer='Cadwell'; content='electrophysiological data'`), add `case 'cadwell_sqlite'` to `ft_read_header/data/event` calling the private reader, put the reader in `fieldtrip/fileio/private/`, and if it depends on an external library add it under `fieldtrip/external/<lib>` and gate with `ft_hastoolbox('<LIB>',1)`. Since ft_read_* is shared with SPM and EEGLAB (File-IO plugin), an upstream reader automatically becomes an EEGLAB importer via `pop_fileio`.
- Existing EDF support: `ft_filetype` maps `.edf` → `'edf'` (extension only); `ft_read_header` calls `read_edf(filename)` (or `read_edf(filename,[],chanindx)`); `read_edf` picks the channel subset with a common sampling rate (last-channel annotation exception) and exposes EDF+ annotations via `hdr.orig.annotation` for `ft_read_event`. There is **no Cadwell code anywhere in fileio** (grep of ft_filetype/ft_read_* for "cadwell" returns nothing).

Code: https://github.com/fieldtrip/fieldtrip/blob/master/fileio/{ft_read_header.m,ft_read_data.m,ft_read_event.m,ft_filetype.m,private/read_edf.m}.
